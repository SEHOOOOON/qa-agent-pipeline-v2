1 프로젝트 배경

일관된 품질 판단 기준의 필요성

검토자의 경험에 따라 달라지는 테스트 범위와 AI가 근거 없는 기대값을 만드는 문제를 줄이고자 했습니다.

!

반복해서 마주한 문제

  • 같은 요구사항도 작성자에 따라 테스트 범위가 달라짐
  • AI가 요구사항에 없는 기대값을 만들어냄
  • 모호한 TC가 자동화와 보고 단계까지 이어짐
✓

  • 실무 QA 판단 기준을 3단계 품질 기준으로 정리
  • AI가 정해진 형식으로 분석·TC·자동화 계획을 생성
  • 프로그램이 산출물을 검사하고 실행 증거로 결과를 확인

최저 온도를 16°C로 잘못 작성

요구사항은 자동 모드에서 18~30°C만 허용하는 것입니다. AI가 이를 16~30°C로 분석하면, 잘못된 기준으로 테스트를 만들게 됩니다.

요청과 다른 온도 기준 · 수정 필요

18°C 기준을 확인한 뒤 테스트 설계로 전달

요구사항 검사 로직(Checkpoint 1)은 사용자가 입력한 최저 온도 18°C와 AI가 분석한 최저 온도 16°C를 비교합니다. AI는 확인된 오류를 전달받아 분석을 다시 작성합니다. 시스템은 수정된 분석을 재검사하고, 통과한 결과만 테스트 설계 단계로 전달합니다.

4 Agent 2 · TC 설계와 품질 검토

3단계 품질 기준을 적용한 TC 설계

Agent 2는 확정 조건과 기존 TC를 바탕으로 실제 AI 모델이 테스트를 설계합니다. 재사용할 검증과 신규 검증을 구분하고, 아래 QA 관점을 설계에 적용하며, 자동 검사는 명시 값·연결 관계·준비·시험·복원 등 확인 가능한 항목을 대조합니다.

1단계

공통 QA 기준

모든 기능에 공통으로 적용하는 기본 검토 기준입니다.

  • 정상·예외·경계값
  • 상태 변경과 회귀 영향
  • 각 테스트의 독립 실행
  • 정보 부족 여부
2단계

중앙제어 도메인 기준

중앙제어 시스템에서 중요하게 다루는 위험을 확인합니다.

  • 모드별 제어 제한
  • 연결·알람·잠금 표시 상태
  • 대상 장비의 화면·상태값 일치
  • 비대상 장비의 변경 여부
3단계

기능별 품질 기준

실제 테스트와 자동화에 필요한 판단 조건을 구체화합니다.

  • 근거가 확인된 기대결과만 사용
  • 통과·실패 판단 기준
  • 기능에 맞는 검증 대상 선택
  • 자동화 가능 범위

TC 설계 결과에서 자동으로 확인하는 항목

1. 기획 근거성

요구사항의 출처·명시 코드·수치를 대조하고 근거 밖 값을 검사

2. 독립 실행 조건 검토

다른 TC에 의존하지 않는 사전조건·시험 절차·복원 확인

3. 명확성 검증

어떤 조작 뒤 무엇을 관찰하는지 기대결과와 시점을 확인

4. 자동화 적합성

검증 가능한 절차인지 검토하고 실제 요소·계획 검사는 Agent 3에서 수행

Checkpoint 2를 통과하지 못하면 AI에 기존 TC와 검사 결과를 보내 한 번 수정한 뒤 다시 검사합니다. 그래도 실패하면 Agent 3로 넘기지 않습니다. 생성된 TC는 시험할 후보이며, SRS 변경안 반영과 공식 TC 등록은 사람 승인 후에 이루어집니다.

기존 TC가 있는데 왜 새로 만드나요?

기존 TC로 충분하면 새로 만들지 않습니다. 변경 요구사항을 기존 TC가 검증할 수 있으면 해당 TC를 선택해 재실행합니다.

확인할 조건이나 결과가 달라졌다면 부족한 부분만 추가합니다. 같은 기능의 TC라도 시험하는 입력값·상태·관찰 대상이 다르면 새 요구사항을 모두 확인하지 못할 수 있습니다.

이름이 비슷한지만 보는 것이 아니라, 기존 TC의 실제 절차와 기대결과를 변경 요구사항과 비교합니다.

5 Agent 3 · 자동화 구현과 실행

AI 계획 → 코드 생성 → 실제 시험

Agent 2에서 검토한 TC와 테스트에 필요한 화면 요소·상태를 입력받습니다. AI는 실행 계획을 만들고, Checkpoint 3가 원래 TC와 대조한 뒤 프로그램이 코드로 변환해 실제 시험을 수행합니다.

실제 실행 사례 · 중풍 표시 변경

변경 요구사항 풍량을 ‘중풍’으로 바꾸면, 장비 카드에 중풍이 표시되고 내부 풍량 설정도 중풍으로 변경되어야 합니다.

AI는 TC의 사전조건·절차·기대결과·복원을 읽고, 관찰한 버튼과 상태값에 연결합니다. 요구사항을 새로 해석해 기대값을 바꾸는 단계는 아닙니다.

  1. 01
    중풍을 선택하고 적용

    관제 패널에서 대상 장비의 풍량을 바꿉니다.

  2. 02
    화면과 내부 설정을 함께 확인

    카드에 ‘중풍’이 보이고 내부 풍량도 중풍인지 비교합니다.

  3. 03
    시험 전 상태로 복원

    다음 테스트에 영향을 주지 않도록 처음 풍량으로 되돌립니다.

  • 요청한 변경·기대값과 실제 시험 결과 비교
  • 실패 증거·제외 사유·미확인 항목 검토
  • 검토자·승인/보류 판단·메모를 기록하고 TC·코드·실행 출처 보존
SRS 개정 동의
  • 요구사항 명세서(SRS)의 변경 전·후 문구 비교
  • 새 제품 기준으로 반영할지 별도로 동의
  • 승인 전에는 기존 명세 유지
회귀 테스트 등록
  • 통과한 후보의 사전조건·절차·기대결과·복원 검토
  • TC와 자동화 코드가 일치하는지 확인
  • 다음 변경에도 재사용할 공식 테스트로 등록할지 결정
보류
  • 보류 사유와 추가 확인 항목 기록
  • 기존 SRS·공식 테스트는 변경 없이 유지
승인
  • 동의한 SRS 개정과 후보 TC·자동화 코드를 공식 자산에 반영
  • 다음 변경 요청에서 Agent 2가 관련 테스트의 재사용 여부 검토
예시현재 등록 상태 · 강풍·중풍 공식 TC현재 자산 상태 · 두 공식 TC와 과거 후보 구분등록 판단

등록 기준 시험 통과와 공식 등록은 별개입니다. 사람이 결과를 검토하고 SRS 개정·TC 등록 여부를 결정합니다.

  • 최종 실행·자동 검사 통과와 필수 증거 확인

8 구현 영상

요구사항부터 시험·사람 판단까지

변경 요청을 테스트로 만들고, 실행 결과를 확인한 뒤 공식 자산으로 등록하는 흐름을 90초로 담았습니다.

90초 · 실제 기록과 승인 장면 · 무음·화면 설명 포함

중풍 표시 변경의 테스트 설계·실행·공식 등록, 잠금 시험의 실패 보고, 알림 색상이 미정인 경우의 부분 진행을 보여줍니다.

  • 정상 변경 → 요구사항 명세서(SRS) 반영·공식 테스트케이스(TC) 등록
  • 잠금 시험 실패 → 제품 불일치 후보 보고
  • 색상 미정 → 확정 범위 시험·사람 검토

실제 저장된 실행 기록과 사용자 승인에 따른 대행 등록 장면의 편집본입니다. 새 AI 실행 전 과정을 실시간으로 녹화한 영상은 아닙니다. 본문에서 설계를 설명하고, 영상에서는 실제 연결과 결과를 확인할 수 있습니다.

9 프로젝트 가치

이 프로젝트에서 확인한 QA 가치

TC 생성 자체보다 변경 범위·시험 근거·기준 반영의 책임을 연결하는 데 초점을 두었습니다.

변경분과 기존 자산을 함께 관리

중풍 변경은 신규 TC로 검증하고, 관련 강풍 검증은 승인된 TC를 재사용했습니다. 새 검증을 추가하면서 기존 검증도 유지하는 흐름을 확인했습니다.

통과 수치와 검증 범위를 구분

시험이 모두 통과한 경우에도 미정 조건을 별도로 남겼습니다. PASS 수치만으로 요청 전체가 검증됐다고 판단하지 않습니다.

시험 결과와 공식 기준을 구분

검증된 결과가 곧바로 제품 기준이 되지는 않습니다. 사람이 SRS 변경과 재사용할 테스트를 결정하고, 등록 근거를 기록하도록 연결했습니다.

10 현재 한계점

구현 범위와 아직 증명하지 않은 것

가상 중앙제어의 MODIFIED 요청이 현재 대상입니다. 대표 실행 성공과 범용 적용·반복 품질은 구분합니다.

복합 자연어의 의미

코드만으로는 같은 값으로 다른 의미를 쓴 오류까지 자동 판정하지는 못합니다. 새 실행에 별도 모델 근거 검토를 추가했으며, 실제 모델의 검토 정확도는 아직 검증 전입니다. 공개 사례는 도입 전 기록입니다.

지원하는 자동화 범위

관찰 가능한 화면 요소와 허용된 조작·검증 계획이 필요합니다. 모든 웹을 자동화하지는 않습니다.

가상 환경과 실제 장비

실제 장비 통신·물리 예외·전체 회귀는 현재 검증 범위 밖입니다.

호출 비용과 실행 편차

생성뿐 아니라 근거 검토에도 API 비용이 발생합니다. 모델의 오판·재작성·시간 초과와 반복 품질 평가는 아직 남아 있습니다.

11 향후 로드맵

실무 타당성과 반복 품질 평가

프로젝트 2에서 실제 QA 판단 기준과 모델 산출물을 대조할 계획입니다.

TC의 유효성 평가

요구사항 근거·필수 검증 누락·실행 가능성을 사람이 검토할 기준과 정답 사례로 정리합니다.

동일 조건 반복 평가

같은 요구사항에서 TC 품질·불필요한 제외·재사용 판단·호출 비용의 편차를 측정합니다.

사람의 수정 부담 확인

생성 결과를 실무에서 채택하려면 얼마나 검토·수정해야 하는지 확인합니다.

12 주요 산출물

문서와 실행 증거

공개 실행 자료는 당시 증거입니다. 최신 수치·Run·미해결 사항은 인계 문서에서 관리하며, 로컬 전용 결과는 내려받은 저장소에 포함되지 않을 수 있습니다.
