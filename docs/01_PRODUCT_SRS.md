## 2. 시스템 개요

### Summary

가상 중앙제어 시스템은 웹 관제 패널에서 16대 실내기를 조회하고 단일 또는 복수 장비를 제어하는 시뮬레이터입니다. 시스템은 사용자 역할, 연결, 오류와 잠금 상태를 검사한 뒤 허용 장비에만 전원, 모드, 설정 온도, 풍량과 잠금 명령을 반영합니다.

### Input/Output Relationship(입출력 관계)

**입력**

- 장비 선택과 복수 선택 전환
- 전원·모드·설정 온도·풍량·잠금 대기값과 적용 명령
- ADMIN·VIEWER 역할 상태와 °C·°F 표시 단위
- 게이트웨이·장비 오류에 따른 상태 변화

**출력**

- 장비 카드, 선택 상태, 제어 패널과 전체 상태 요약
- 적용·차단·오류에 대한 사용자 안내 Toast
- 중앙제어 후 사용자 화면과 내부 장비 상태
- 새로고침 후 복원되는 시뮬레이션 상태

### 식별자와 기본 상태

- 화면 표시명은 IDU-00~IDU-15이며 총 16대입니다.
- 내부 숫자 ID는 1~16이며 화면 표시명과 구분합니다.
- 저장 상태가 없는 최초 로드는 STOP, COOL, 24°C, LOW, 잠금 해제입니다.
- 최초 사용자 역할은 ADMIN, 게이트웨이는 온라인입니다.

### 공통 용어

| 용어 | 의미 |
|---|---|
| 대기값 | 제어 패널에서 변경했지만 아직 장비에 적용하지 않은 값 |
| 대상 장비 | 단일 또는 복수 선택 목록에 포함된 장비 |
| 비대상 장비 | 선택 목록에 포함되지 않은 장비 |
| 중앙 명령 | 적용 버튼을 통해 대상 장비로 전달하는 명령 |
| 내부 장비 상태 | 시뮬레이터가 관리하는 장비별 상태 데이터 |

## 3. 장비 로드·조회·선택

### Summary

시스템은 장비 16대를 표시하고 단일·복수 선택 상태를 관리합니다.

### Input/Output Relationship(입출력 관계)

- 입력: 페이지 로드, 장비 카드 선택, 복수 선택 전환
- 출력: 장비 카드 16개, 장비별 현재·설정 온도, 선택 강조, 선택 목록과 제어 패널 활성 상태

### Normal/Alternative Flow(정상/대안 동작)

1. 저장 상태가 없으면 기본 상태의 장비 16대를 로드합니다.
2. 단일 선택은 마지막 선택 장비 한 대만 유지합니다.
3. 복수 선택은 장비를 대상 목록에 추가하거나 제거합니다.
4. 대상 장비가 없으면 제어 패널을 사용할 수 없는 상태로 표시합니다.
5. 전체 상태 요약에는 운전·정지·오류 장비 수를 표시합니다.
6. 각 장비 카드에는 현재 온도와 설정 온도를 구분하여 표시합니다.

### Exception Handling(예외 처리)

- 대상 장비가 없으면 중앙 명령을 적용하지 않고 사유를 안내합니다.

### Constraints(제약사항)

- 17번째 이상의 장비는 지원 범위가 아닙니다.
- 화면 표시명과 내부 숫자 ID를 같은 값으로 간주하지 않습니다.

### State Consistency Requirement(상태 정합성 요구사항)

- 카드 선택 표시와 내부 선택 목록이 같아야 합니다.
- 운전·정지·오류 요약 수의 합은 16이어야 합니다.

### Relation with other Requirement(다른 요구사항과의 연관관계)

- REQ-CONTROL-001, REQ-BATCH-001, REQ-STATE-001

| ID | 요구사항 | 인수 기준 |
|---|---|---|
| REQ-ENV-001 | 장비 16대를 로드해야 합니다. | 화면에 IDU-00~IDU-15 카드 16개가 표시되고 내부 장비 수도 16입니다. |
| REQ-SELECT-001 | 단일·복수 장비 선택을 지원해야 합니다. | 단일 선택은 한 대만, 복수 선택은 선택 목록을 유지하며 화면 표시와 내부 목록이 같습니다. |
| REQ-OVERVIEW-001 | 전체 장비 상태 요약을 표시해야 합니다. | 운전·정지·오류 수가 표시되고 합계가 16입니다. |
| REQ-MONITOR-001 | 장비별 현재 온도와 설정 온도를 구분하여 표시해야 합니다. | 카드의 현재 온도는 내부 currentTemp와, 설정 온도는 온도 활성 모드에서 내부 setTemp와 같습니다. FAN·DRY의 설정 온도는 비활성 표시를 사용합니다. |

## 4. 중앙 제어와 복수 적용

### Summary

제어 패널의 대기값은 적용 전까지 장비를 바꾸지 않으며, 적용 시 허용 조건을 만족한 대상 장비에만 반영됩니다.

### Input/Output Relationship(입출력 관계)

- 입력: 대상 장비, 전원·모드·온도·풍량·잠금 대기값, 적용 명령
- 출력: 대상 장비의 사용자 화면·내부 상태와 처리 결과 안내

### Normal/Alternative Flow(정상/대안 동작)

1. 장비 선택 시 현재 상태를 제어 패널 대기값으로 표시합니다.
2. 대기값 변경만으로는 실제 장비 상태를 변경하지 않습니다.
3. 적용 시 역할, 게이트웨이, 장비 오류와 잠금 정책을 검사합니다.
4. 허용 장비에는 대기값을 반영하고 차단 장비에는 기존 상태를 유지합니다.
5. 복수 선택은 장비별 허용 조건을 독립적으로 검사합니다.
6. 잠긴 장비에는 잠금 해제 명령만 허용합니다.

### Alternative Flow(대안 동작)

- 허용 장비와 차단 장비가 함께 있으면 허용 장비만 반영하고 처리 결과를 안내합니다.

### Exception Handling(예외 처리)

- VIEWER, 게이트웨이 오프라인, 오류 장비와 잠금 장비의 제한 명령은 적용하지 않습니다.

### Constraints(제약사항)

- 복수 적용은 원자적 트랜잭션이 아니라 장비별 허용 결과를 반영합니다.
- 역할 전환 UI는 이 기준 범위에 포함하지 않으며, REQ-AUTH-001은 VIEWER 역할 상태가 주어진 경우의 제어 정책을 정의합니다.
- 성공은 브라우저 시뮬레이터 반영이며 실제 통신 성공을 의미하지 않습니다.

### State Consistency Requirement(상태 정합성 요구사항)

- 허용 대상의 화면과 내부 상태가 같아야 합니다.
- 비대상 장비와 차단 대상은 실행 전 상태를 유지해야 합니다.

### Relation with other Requirement(다른 요구사항과의 연관관계)

- REQ-AUTH-001, REQ-GATEWAY-001, REQ-LOCK-001, REQ-ERROR-001

| ID | 요구사항 | 인수 기준 |
|---|---|---|
| REQ-CONTROL-001 | 제어 패널 대기값은 적용 후 허용 장비에 반영되어야 합니다. | 적용 전 상태는 유지되고 적용 후 허용 대상의 화면과 내부 상태는 기능별 표시 규칙을 반영해 같은 동작 의미를 나타냅니다. |
| REQ-POWER-001 | 장비 전원을 OPERATION 또는 STOP으로 설정할 수 있어야 합니다. | 적용 후 카드 상태와 내부 status가 선택한 값과 같습니다. |
| REQ-AUTH-001 | VIEWER 역할의 중앙 명령을 차단해야 합니다. | VIEWER에서 적용 후 대상 상태가 유지되고 차단 안내가 표시됩니다. |
| REQ-BATCH-001 | 복수 선택한 허용 장비에 공통값을 적용해야 합니다. | 허용된 선택 장비 각각의 화면·내부 상태가 요청값으로 변경됩니다. |
| REQ-BATCH-002 | 비대상 장비와 차단 장비의 상태를 변경하지 않아야 합니다. | 실행 전후 비대상 및 차단 대상의 관련 상태값이 같습니다. |

## 5. 모드·설정 온도·풍량

### Summary

시스템은 5개 모드와 4개 풍량을 제공하며 모드와 표시 단위에 따라 설정 온도 입력 가능 여부와 표시값을 결정합니다.

### Input/Output Relationship(입출력 관계)

- 입력: COOL·HEAT·FAN·DRY·AUTO, 온도 +/−, LOW·MED·HIGH·AUTO, °C·°F
- 출력: 활성 모드, 설정 온도 또는 ---, 제한 범위 안내와 풍량

### Normal/Alternative Flow(정상/대안 동작)

- COOL·HEAT·AUTO에서는 온도 입력을 활성화합니다.
- FAN·DRY에서는 온도 입력을 비활성화하고 ---를 표시합니다.
- FAN·DRY에서 COOL·HEAT·AUTO로 전환하면 온도 입력을 다시 활성화합니다.
- °C·°F 전환은 표시값만 변환하고 내부 온도는 섭씨로 유지합니다.
- 섭씨 설정 범위는 16~30°C이고 화씨 화면에는 61~86°F를 표시합니다.

### Exception Handling(예외 처리)

- 허용 범위 밖 온도 요청은 적용하지 않고 기존 설정 온도를 유지합니다.
- FAN·DRY에서는 관제 패널의 온도 변경을 적용하지 않습니다.

### Constraints(제약사항)

- 모드별 별도 온도 범위는 변경 요구사항으로 승인되기 전까지 초기 기준에 포함하지 않습니다.

### State Consistency Requirement(상태 정합성 요구사항)

- 모드 전환 시 온도 입력 상태와 표시값이 함께 갱신되어야 합니다.
- 차단된 온도 요청은 화면과 내부 설정 온도를 모두 변경하지 않아야 합니다.

### Relation with other Requirement(다른 요구사항과의 연관관계)

- REQ-CONTROL-001, REQ-NOTIFY-001, REQ-STATE-001

| ID | 요구사항 | 인수 기준 |
|---|---|---|
| REQ-MODE-001 | COOL·HEAT·FAN·DRY·AUTO 모드를 선택할 수 있어야 합니다. | 적용 후 제어 패널·카드·내부 mode가 선택한 값과 같습니다. |
| REQ-MODE-002 | FAN·DRY에서 설정 온도 입력을 비활성화해야 합니다. | 온도 조작 버튼이 disabled이고 설정 온도 표시가 ---입니다. |
| REQ-TEMP-001 | 섭씨 설정 범위는 16~30°C여야 합니다. | 범위 안 요청은 반영되고 범위 밖 요청은 차단되며 화면·내부 설정 온도가 기존 값을 유지합니다. |
| REQ-TEMP-002 | °C·°F 표시 단위를 전환할 수 있어야 합니다. | 표시 단위와 값은 변환되고 내부 설정 온도는 동일한 섭씨 값으로 유지됩니다. |
| REQ-FAN-001 | LOW·MED·HIGH·AUTO 풍량을 선택할 수 있어야 합니다. | 적용 후 내부 fanSpeed는 선택한 코드와 같고, HIGH는 장비 카드에 사용자용 한글 라벨 강풍으로 표시됩니다. |

## 6. 잠금·오류·게이트웨이 동작

### Summary

잠금, 장비 오류와 게이트웨이 상태는 중앙 관제 명령의 허용 범위를 제한합니다.

### Input/Output Relationship(입출력 관계)

- 입력: 잠금·오류·게이트웨이 상태와 중앙 관제 명령
- 출력: 장비 상태, 오류 코드, 제어 허용·차단 결과와 사용자 안내

### Normal/Alternative Flow(정상/대안 동작)

- 잠금 장비는 잠금 해제 외 중앙 관제 명령을 차단합니다.
- 오류 장비는 ERROR와 오류 코드를 표시하고 중앙 관제 명령을 차단합니다.
- 오류 해제 후 오류 코드를 제거하고 STOP으로 전환합니다.
- 게이트웨이 오프라인에서는 모든 장비를 OFFLINE으로 표시하고 중앙 제어를 비활성화합니다.
- 게이트웨이 복구 시 오류 장비는 ERROR, 그 밖의 OFFLINE 장비는 STOP으로 전환합니다.

### Constraints(제약사항)

- CH05·CH21은 시뮬레이션 오류 코드이며 실제 장비 알람 정의가 아닙니다.
- QA Drawer 버튼은 상태를 만드는 테스트 도구이며 제품 요구사항이 아닙니다.

### State Consistency Requirement(상태 정합성 요구사항)

- 차단된 중앙 관제 명령은 관련 상태를 변경하지 않아야 합니다.
- 오류·연결 상태와 카드 표시가 일치해야 합니다.

### Relation with other Requirement(다른 요구사항과의 연관관계)

- REQ-CONTROL-001, REQ-NOTIFY-001, REQ-STATE-001

| ID | 요구사항 | 인수 기준 |
|---|---|---|
| REQ-LOCK-001 | 잠금 장비의 잠금 해제 외 중앙 관제 제어를 차단해야 합니다. | 차단 명령 후 관련 상태가 유지되고 차단 안내가 표시됩니다. |
| REQ-ERROR-001 | 오류 장비의 중앙 관제 제어를 차단해야 합니다. | ERROR와 오류 코드가 표시되고 차단 명령 후 관련 상태가 유지됩니다. |
| REQ-ERROR-002 | 오류 해제 후 장비를 STOP으로 전환해야 합니다. | 오류 코드가 제거되고 카드·내부 상태가 STOP입니다. |
| REQ-GATEWAY-001 | 게이트웨이 오프라인에서 중앙 명령을 차단해야 합니다. | 모든 장비가 OFFLINE이고 중앙 명령 후 상태가 변경되지 않습니다. |
| REQ-GATEWAY-002 | 게이트웨이 복구 시 장비 상태를 재구성해야 합니다. | 오류 장비는 ERROR, 그 밖의 장비는 STOP입니다. |

## 7. 상태 정합성·알림·상태 유지

### Summary

제어 결과는 사용자 화면과 내부 장비 상태에서 일관되게 표현되고 주요 결과는 사용자가 확인할 수 있어야 합니다.

### Input/Output Relationship(입출력 관계)

- 입력: 중앙 관제 명령, 역할·단위·연결 변경, 페이지 새로고침
- 출력: 카드·제어 패널·상태 요약, Toast, 복원된 시뮬레이션 상태

### Normal/Alternative Flow(정상/대안 동작)

- 허용 명령 후 카드와 제어 패널에 최신 상태를 표시합니다.
- 차단·성공·상태 전환 결과를 Toast로 안내합니다.
- 장비, 게이트웨이, 선택 목록과 복수 선택 상태를 새로고침 후 복원합니다.

### Exception Handling(예외 처리)

- 사용자 안내는 실제 명령 성공 여부와 반대되는 내용을 표시하지 않아야 합니다.
- 복원할 수 없는 저장값을 정상 상태로 추정하지 않습니다.

### Constraints(제약사항)

- 저장 방식과 저장 키는 구현 상세이므로 제품 SRS에서 고정하지 않습니다.
- Toast 문구는 변경 요청이 정확한 문구를 요구할 때만 문자열 일치 기준으로 사용합니다.
- QA 이벤트 로그와 내부 Register 조회는 QA 하네스에서 정의합니다.

### State Consistency Requirement(상태 정합성 요구사항)

- 카드·제어 패널과 내부 상태의 공통 필드는 같아야 합니다. 현재 온도와 설정 온도는 서로 다른 값으로 구분합니다.
- 차단 안내가 표시되면 차단 대상의 관련 상태는 실행 전과 같아야 합니다.

### Relation with other Requirement(다른 요구사항과의 연관관계)

- 모든 상태 변경·차단 요구사항

| ID | 요구사항 | 인수 기준 |
|---|---|---|
| REQ-STATE-001 | 사용자 화면과 내부 장비 상태가 일치해야 합니다. | status·mode·currentTemp·setTemp·locked 등 같은 표현을 쓰는 공통 값은 일치하고, fanSpeed처럼 사용자 라벨과 내부 코드가 다른 필드는 기능별 표시 규칙에 따라 같은 동작 의미를 나타냅니다. |
| REQ-NOTIFY-001 | 주요 적용·차단·오류 결과를 사용자에게 안내해야 합니다. | 처리 결과와 일치하는 Toast가 표시되며 차단 안내 시 대상 상태가 유지됩니다. |
| REQ-PERSIST-001 | 시뮬레이션 상태를 저장하고 새로고침 후 복원해야 합니다. | 장비·게이트웨이·선택 목록·복수 선택 상태가 새로고침 전과 같습니다. |

## 8. 공통 품질 및 제약

### Quality Requirement(품질 요구사항)

- 같은 초기 상태와 같은 입력에는 같은 장비 상태 결과가 나와야 합니다.
- 명령 허용 여부와 사용자 안내가 모순되지 않아야 합니다.
- 상태 변경은 사용자 화면과 내부 장비 상태를 함께 판정할 수 있어야 합니다.
- 일부 장비만 처리된 복수 명령을 전체 성공으로 표시하지 않아야 합니다.

### Constraints(제약사항)

- 단일 브라우저에서 실행되는 관제 패널 시뮬레이터입니다.
- 실제 장비 통신, 서버 영속 저장, 다중 사용자 동시성, 장애 이중화는 지원하지 않습니다.
- 승인된 근거가 없는 성능 수치를 임의로 요구사항에 추가하지 않습니다.
- 숨김·데모 기능을 정상 제품 기능으로 추론하지 않습니다.

## 9. 초기 제품 기준 확정 원칙

- 요구사항은 기대 동작을 설명하고 코드·Selector·테스트 방법을 설명하지 않습니다.
- 화면 정책과 코드가 충돌하면 구현 감사에 기록합니다.
- 알려진 결함과 Pipeline Fixture를 정상 요구사항 근거로 사용하지 않습니다.
- V2 최초 실행 전에 사람이 이 문서를 변경 전 기준으로 한 번 검토합니다.
- 이후 변경 요청은 최종 보고와 정식 QA 자산 등록 결정 전까지 이 문서를 덮어쓰지 않습니다.
