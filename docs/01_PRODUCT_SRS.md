# 가상 중앙제어 시스템 제품 요구사항 명세서

## 1. 문서 정보

| 항목 | 내용 |
|---|---|
| 문서 상태 | V2 설계용 초기 제품 기준 문서 후보 |
| 대상 | 프로젝트 1 `virtual-controller.html` |
| 근거 | 실제 화면, JavaScript 제어 로직, 기존 Playwright TC |
| 성격 | 회사 공식 SRS가 아닌 구현 역추적 명세 |

이 문서는 가상 중앙제어기에서 **현재 확인되는 제품 동작만** 정의합니다. Agent 시연 화면, 결과 분류 Fixture, 앞으로 구현할 V2 모델 호출·실행기는 제품 요구사항에 포함하지 않습니다.

## 2. 시스템 개요

### Summary

가상 중앙제어 시스템은 웹 화면에서 16대 실내기를 조회·제어하는 로컬 시뮬레이터입니다. 단일 또는 복수 장비를 선택해 전원, 모드, 설정 온도, 풍량과 잠금을 변경하며 사용자 역할, 게이트웨이, 오류와 잠금 상태에 따라 중앙 명령 허용 여부를 결정합니다.

### Input/Output Relationship(입출력 관계)

**입력**

- 장비 선택과 복수 선택 전환
- 전원·모드·설정 온도·풍량·잠금과 적용 명령
- ADMIN·VIEWER 역할, °C·°F 단위
- 게이트웨이 연결·해제, 오류 주입·해제
- 현장 전원·온도 조작

**출력**

- 장비 카드·제어 패널·상태 요약
- H/W Register 시뮬레이터
- Toast·QA 이벤트 로그
- 브라우저 localStorage 상태

### 시스템 경계

- IDU-00~IDU-15, 총 16대만 지원합니다.
- 실제 장비, 실제 Modbus 주소, 운영 게이트웨이와 연결하지 않습니다.
- Register는 HTML로 표현한 시뮬레이션 상태입니다.
- `window.__vccs`는 기존 Playwright가 상태를 읽기 위한 테스트 인터페이스입니다.
- Agent 1~4 시연 UI는 제품 기능과 분리합니다.

## 3. 장비 로드·조회·선택

### Summary

시스템은 장비 16대를 표시하고 단일·복수 선택을 지원합니다.

### Input/Output Relationship(입출력 관계)

- 입력: 페이지 로드, 장비 카드 클릭, 복수 선택 전환
- 출력: 장비 카드, 선택 표시, 선택 장비 정보, 제어 패널 활성 상태

### Normal/Alternative Flow(정상/대안 동작)

- 최초 기본값은 STOP, COOL, 24°C, LOW, 잠금 해제입니다.
- 단일 선택은 마지막 클릭 장비 한 대만 유지합니다.
- 복수 선택은 클릭 장비를 선택 목록에 추가하거나 제거합니다.
- 선택 장비가 없으면 제어 영역을 비활성화합니다.
- localStorage 상태가 있으면 기본값 대신 저장 상태를 불러옵니다.

### Additional Flow(부가 동작)

- 운전·정지·오류 장비 수를 요약합니다.
- 선택 상태와 복수 선택 여부를 저장합니다.

### Exception Handling(예외 처리)

- 선택 장비가 없으면 적용 명령을 수행하지 않습니다.

### Constrain(제약사항)

- 17번째 이상 장비는 지원하지 않습니다.
- 저장 데이터 Schema 마이그레이션은 구현되어 있지 않습니다.

### Quality Requirement(품질 요구사항)

- 화면 카드 수와 내부 `devices` 수는 모두 16이어야 합니다.
- 화면 선택과 내부 선택 ID가 일치해야 합니다.

### Relation with other Requirement(다른 요구사항과의 연관관계)

- REQ-CONTROL-001, REQ-BATCH-001, REQ-STATE-001

| ID | 요구사항 | 인수 기준 |
|---|---|---|
| REQ-ENV-001 | 장비 16대를 로드해야 합니다. | 카드와 내부 장비가 각각 16개입니다. |
| REQ-SELECT-001 | 단일·복수 선택을 지원해야 합니다. | 선택 카드와 내부 선택 ID가 일치합니다. |
| REQ-OVERVIEW-001 | 전체 상태 요약을 표시해야 합니다. | 운전·정지·오류 수 합계가 16입니다. |

## 4. 중앙 제어와 복수 적용

### Summary

제어 패널 변경값은 적용 버튼을 누른 뒤 허용된 대상 장비에 반영됩니다.

### Input/Output Relationship(입출력 관계)

- 입력: 전원, 모드, 온도, 풍량, 잠금의 대기값과 적용
- 출력: 대상 장비 상태, 카드, Register, 처리 로그와 Toast

### Normal/Alternative Flow(정상/대안 동작)

1. 장비 선택 시 현재 상태를 대기값으로 가져옵니다.
2. 사용자가 대기값을 변경한 뒤 적용합니다.
3. ADMIN, 게이트웨이 온라인, 장비 오류와 잠금 정책을 검사합니다.
4. 허용 장비에 변경을 반영하고 카드·Register를 갱신합니다.
5. 복수 선택에서는 장비별 상태를 확인해 허용된 장비만 처리합니다.
6. 잠긴 장비에는 잠금 해제 명령만 허용합니다.

### Additional Flow(부가 동작)

- 변경 항목과 장비별 처리 결과를 로그로 남깁니다.
- 적용·오류·잠금 장비 수를 Toast로 표시합니다.

### Exception Handling(예외 처리)

- VIEWER, 게이트웨이 오프라인, ERROR 장비와 잠금 장비의 명령을 차단합니다.

### Constrain(제약사항)

- 복수 제어는 원자적 트랜잭션이 아니라 장비별 처리입니다.
- 실제 통신 응답이 아닌 시뮬레이터 상태 변경을 성공으로 표시합니다.

### Quality Requirement(품질 요구사항)

- 차단 장비의 상태는 변경되지 않아야 합니다.
- 대상만 변경되고 비대상 장비는 유지되어야 합니다.
- 적용 장비의 화면과 내부 상태가 일치해야 합니다.

### Relation with other Requirement(다른 요구사항과의 연관관계)

- REQ-AUTH-001, REQ-GATEWAY-001, REQ-LOCK-001, REQ-ERROR-001

| ID | 요구사항 | 인수 기준 |
|---|---|---|
| REQ-CONTROL-001 | 변경값은 적용 후 반영되어야 합니다. | 적용 전 원상태, 적용 후 대기값과 같습니다. |
| REQ-POWER-001 | OPERATION·STOP을 설정해야 합니다. | 카드와 내부 status가 같습니다. |
| REQ-AUTH-001 | VIEWER의 중앙 명령을 차단해야 합니다. | 상태 불변과 차단 로그가 확인됩니다. |
| REQ-BATCH-001 | 선택 장비에 공통값을 적용해야 합니다. | 허용 대상의 상태가 변경됩니다. |
| REQ-BATCH-002 | 비대상 장비를 변경하지 않아야 합니다. | 실행 전후 비대상 상태가 같습니다. |

## 5. 모드·설정 온도·풍량

### Summary

시스템은 5개 모드와 4개 풍량을 제공하며 모드에 따라 온도 입력을 제한합니다.

### Input/Output Relationship(입출력 관계)

- 입력: COOL·HEAT·FAN·DRY·AUTO, 온도 +/−, LOW·MED·HIGH·AUTO, °C·°F
- 출력: 활성 모드, 설정 온도 또는 `---`, 제한 범위, 풍량, 카드·Register

### Normal/Alternative Flow(정상/대안 동작)

- COOL·HEAT·AUTO에서는 온도 입력을 활성화합니다.
- FAN·DRY에서는 온도 입력을 비활성화하고 `---`를 표시합니다.
- FAN·DRY에서 COOL로 돌아오면 온도 입력을 다시 활성화합니다.
- °C/°F 전환은 표시값만 변환하고 내부 온도는 섭씨로 유지합니다.
- 섭씨 화면은 16~30°C, 화씨 화면은 61~86°F를 안내합니다.

### Additional Flow(부가 동작)

- 카드와 온도 표시 스타일을 선택 모드에 맞게 갱신합니다.

### Exception Handling(예외 처리)

- 상한을 넘는 온도 조작을 차단합니다.
- FAN·DRY의 중앙·현장 온도 변경을 차단합니다.

### Constrain(제약사항)

- 현재 하한 코드는 화면 정책 16°C와 다르게 15°C까지 허용합니다. 이는 정상 요구사항이 아니라 **알려진 결함 주입**입니다.
- AUTO 18°C 하한은 공식 요구사항이 아니며 분류 Fixture에서만 사용합니다.

### Quality Requirement(품질 요구사항)

- 모드 변경 전후 온도 입력 상태가 양방향으로 갱신되어야 합니다.
- 차단 조작은 기존 값을 유지해야 합니다.

### Relation with other Requirement(다른 요구사항과의 연관관계)

- REQ-CONTROL-001, REQ-LOCAL-002, REQ-STATE-001

| ID | 요구사항 | 인수 기준 |
|---|---|---|
| REQ-MODE-001 | 5개 모드를 선택할 수 있어야 합니다. | 패널·카드·내부 mode가 일치합니다. |
| REQ-MODE-002 | FAN·DRY에서 온도 입력을 비활성화해야 합니다. | 버튼 disabled와 `---`가 확인됩니다. |
| REQ-TEMP-001 | 섭씨 설정 범위는 16~30°C여야 합니다. | 범위 밖 요청이 차단됩니다. |
| REQ-TEMP-002 | °C·°F 표시를 전환해야 합니다. | 표시 단위가 바뀌고 내부값은 섭씨입니다. |
| REQ-FAN-001 | 4개 풍량을 선택할 수 있어야 합니다. | 적용 후 내부 상태와 Register에 반영됩니다. |

## 6. 잠금·오류·게이트웨이·현장 제어

### Summary

잠금, 오류와 연결 상태에 따라 중앙·현장 제어를 제한합니다.

### Input/Output Relationship(입출력 관계)

- 입력: 잠금, CH05·CH21 오류, 게이트웨이 상태, 현장 전원·온도
- 출력: 장비 상태, 오류 코드, 제어 차단, Toast와 로그

### Normal/Alternative Flow(정상/대안 동작)

- 잠금 장비는 잠금 해제 외 중앙 명령과 현장 전원·온도를 차단합니다.
- 오류 주입 시 장비는 ERROR가 되고 중앙·현장 명령을 차단합니다.
- 오류 해제 후 오류 코드를 제거하고 STOP으로 전환합니다.
- 게이트웨이 오프라인 시 모든 장비를 OFFLINE으로 표시하고 중앙 제어를 비활성화합니다.
- 게이트웨이 복구 시 오류 장비는 ERROR, 나머지 OFFLINE 장비는 STOP으로 전환합니다.
- 정상 온라인에서는 현장 전원 토글과 온도 +/−를 처리합니다.

### Additional Flow(부가 동작)

- 차단 사유와 오류 발생·해제를 QA 로그로 남깁니다.

### Exception Handling(예외 처리)

- 오프라인에서는 오류 주입·해제를 거부합니다.
- 현장 제어 함수는 OFFLINE에서 로그만 남기고 실제 장비 상태를 변경하지 않습니다.

### Constrain(제약사항)

- CH05·CH21은 시뮬레이션 코드이며 실제 장비 알람 정의가 아닙니다.
- 오프라인 현장 제어가 수행된다는 로그 문구는 실제 구현과 달라 요구사항으로 확정하지 않습니다.

### Quality Requirement(품질 요구사항)

- 차단된 중앙·현장 명령은 상태를 변경하지 않아야 합니다.
- 오류·연결 상태와 카드 상태가 일치해야 합니다.

### Relation with other Requirement(다른 요구사항과의 연관관계)

- REQ-CONTROL-001, REQ-LOG-001, REQ-STATE-001

| ID | 요구사항 | 인수 기준 |
|---|---|---|
| REQ-LOCK-001 | 잠금 장비의 중앙·현장 제어를 차단해야 합니다. | 상태 불변과 차단 로그가 확인됩니다. |
| REQ-ERROR-001 | 오류 장비의 중앙·현장 제어를 차단해야 합니다. | ERROR·오류 코드·상태 불변이 확인됩니다. |
| REQ-ERROR-002 | 오류 해제 후 STOP으로 전환해야 합니다. | 오류 코드가 제거되고 STOP입니다. |
| REQ-GATEWAY-001 | 오프라인에서 중앙 명령을 차단해야 합니다. | 모든 장비 OFFLINE과 제어 비활성이 확인됩니다. |
| REQ-GATEWAY-002 | 복구 시 장비 상태를 재구성해야 합니다. | 오류 장비 ERROR, 나머지 STOP입니다. |
| REQ-LOCAL-001 | 정상 상태에서 현장 전원을 토글해야 합니다. | OPERATION·STOP이 전환됩니다. |
| REQ-LOCAL-002 | 허용 모드·범위에서 현장 온도를 변경해야 합니다. | 내부 설정 온도가 ±1°C 변경됩니다. |

## 7. 상태 표시·Register·로그·저장

### Summary

장비 상태를 카드, 제어 패널, Register와 로그로 표현하고 브라우저에 유지합니다.

### Input/Output Relationship(입출력 관계)

- 입력: 상태 변경, 페이지 재로드, 초기화
- 출력: 카드, 패널, Register, 로그, localStorage

### Normal/Alternative Flow(정상/대안 동작)

- Register는 POWER, MODE, FAN, TEMP, LOCK을 표시합니다.
- FAN·DRY의 Register TEMP는 `--`입니다.
- 상태 변경 시 관련 Register 셀을 갱신합니다.
- 장비·게이트웨이·선택 상태를 저장하고 재로드 시 복원합니다.
- 초기화는 확인 후 저장 데이터를 지우고 페이지를 다시 로드합니다.
- Playwright는 `window.__vccs.devices`와 `getRegisterSnapshot()`을 읽을 수 있습니다.

### Additional Flow(부가 동작)

- 로그는 SYSTEM, GATEWAY, LOCAL 출처와 시각·레벨·메시지를 표시합니다.

### Exception Handling(예외 처리)

- 초기화는 사용자 확인 후 수행합니다.

### Constrain(제약사항)

- Register는 DOM 표현이며 실제 백엔드·프로토콜 레지스터가 아닙니다.
- 일반 Snapshot/Restore API와 사전 점검 실패 후 후속 실행 차단은 구현되어 있지 않습니다.
- 로그는 DOM 목록이며 영구 로그 파일이 아닙니다.

### Quality Requirement(품질 요구사항)

- 적용 후 카드·내부 상태·Register 공통 필드가 일치해야 합니다.
- 초기화 후 기본 상태가 다시 로드되어야 합니다.

### Relation with other Requirement(다른 요구사항과의 연관관계)

- 모든 상태 변경 요구사항과 기존 Playwright Double-Assert

| ID | 요구사항 | 인수 기준 |
|---|---|---|
| REQ-STATE-001 | 카드와 내부 상태가 일치해야 합니다. | mode·status·setTemp 등 공통 값이 같습니다. |
| REQ-REGISTER-001 | Register에 제어 상태를 표시해야 합니다. | POWER·MODE·FAN·TEMP·LOCK이 갱신됩니다. |
| REQ-LOG-001 | 주요 제어·차단·오류 이벤트를 표시해야 합니다. | 출처·시각·메시지가 존재합니다. |
| REQ-PERSIST-001 | 상태를 저장하고 재로드 시 복원해야 합니다. | 장비·게이트웨이·선택 상태가 유지됩니다. |

## 10. 초기 제품 기준 문서 확정 원칙

- 모든 Requirement가 실제 화면 또는 코드 근거를 가집니다.
- 알려진 결함을 정상 기대값으로 사용하지 않습니다.
- 테스트 자동화 정책과 제품 요구사항을 혼합하지 않습니다.
- 최초 V2 실행 전에 이 역추적 SRS를 변경 비교의 초기 기준으로 한 번 확정합니다. 이는 매 변경 요청 실행의 중간 승인 단계가 아닙니다.
- 이후 생성된 SRS·TC·자동화 후보는 최종 보고 후 정식 QA 자산 등록을 승인하기 전까지 기존 자산을 덮어쓰지 않습니다.
